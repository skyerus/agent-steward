# Integration setup

Start with the [runtime requirements](docs/runtime.md) on the target host. This installer adds the integration, scheduling, and administration services to that runtime.

On a Linux host with the reviewed OpenClaw stack, isolated native worker and Discord bot, run `sudo SABLE_ADMIN_USERS=<discord-user-id> bash install-integration-setup.sh connect.example.com` from this bundle. Pass a comma-separated list for multiple administrators. Use a hostname reserved for this deployment with its DNS and HTTPS ports directed to the host. Deployment automation can set `SABLE_SIGN_IN_DNS_HOOK` to an authorized provisioning command that receives the hostname.

The installer configures HTTPS, Casbin policy, Luna review, the shared integration setup skill, and Integration Admin. Open a private DM with the Discord bot and ask Integration Admin to set up a named Discord server. An exact server ID locks the install link to that server. For a name, select that exact server in the Discord picker. Someone with Manage Server must Authorise the bot on each server.

After authorization, the VPS verifies the requester and bot's Discord permissions, creates the private channels, and binds the nominated agents. View setup progress or cancel pending setup from the same DM. Each new room has its own user allowlist. Discord is the only external setup integration the Admin needs, and all Discord operations use the installation's bot credential. Integration Admin can create downstream agents and grant their selected account access through the existing reviewed tools. The local provisioning service creates each agent’s writable workspace under the native worker user. The workspace socket is private to the Gateway user.

A downstream agent can connect accounts for itself. A compatible HTTPS MCP server and provider consent are required for a new connection. Use Integration Admin to grant or revoke access for additional agents. Changing a connection's destination clears its credential and grants to other agents.

Every agent uses the shared guide to diagnose integration failures before escalating. Agents can start paired OAuth client registration for their private connections. Integration Admin can manage any connection and controls sharing across agents. GitHub uses the official private GitHub App manifest flow. The requester installs the app on selected repositories and completes user OAuth in GitHub. Other providers can use the paired browser's write-only client credential form. The broker stores credentials against the exact connection and destination revision.

For an OAuth provider that requires advance client registration, use the deployment's `https://<sign-in-host>/oauth/callback` as the callback. Store its registration as an entry in the root-only JSON array `/etc/sable-connection-broker/oauth-clients.json`. Each entry includes `endpoint`, `issuer`, `authorizationEndpoint`, `tokenEndpoint`, `clientId`, and `clientSecret`. Set `authMethod` to `client_secret_basic` when the provider needs HTTP Basic authentication. The default is `client_secret_post`. Restart `sable-connection-broker.service` after updating the file. The broker checks the exact MCP endpoint and discovered OAuth destinations before using the client.

DM Integration Admin to list or change who can message the bot in an existing text channel, or who can DM a specific agent. Routing someone to Integration Admin grants them administrator privileges. The last administrator must remain assigned. Changes pass through Luna and survive installer reruns. Discord itself governs access to private channels.

In an authorised Discord conversation, ask the agent to schedule, list, pause, edit, or remove work. The installer exposes the same scheduling tool to new agents. The broker binds each job to its agent and conversation and uses OpenClaw's Gateway to save it. Jobs use the agent's native workspace and configured model and harness. After switching model accounts, the agent can recreate affected jobs through the same tool so OpenClaw binds the new account. For scheduled integration calls, the broker verifies the live occurrence and native job revision, confirms that the original requester still has access, and submits the verified Discord authorisation to Luna for each call. The reviewer defaults to `openai/gpt-6-luna`. Configure its model and account context separately with the review plugin's `reviewerModel` and `reviewerAgentId` settings.

### Native Git and GitHub MCP

The installer adds the credential-bound Git endpoint to the same private relay used by the native worker. From an authorised Discord DM, Integration Admin can register a private GitHub App for the account and requested read or write permissions. After the owner installs it in GitHub, verification in the paired browser binds GitHub MCP and native Git to one credential record. The browser and Discord receive no signing key. The administrator can then share the connection with selected agents. On a new VPS, run the installer on the reviewed stack and repeat the browser flow for the new deployment.

Integration Admin can deploy reviewed connector source to a downstream agent's `.agent-connectors` directory. The target agent runs that code in its normal workspace. Provider operations still require a broker connection and Luna review. The credential broker, its system services and Git request enforcement are outside the agent-managed workspace.

### Self-service access requests

An agent can request access to any connected MCP integration, a native Git repository backed by a connected GitHub App, or a Discord channel. Use the returned HTTPS approval page. A browser pairs once in an authorised Integration Admin DM, then the same browser can approve later requests. The page shows the exact resource, permission and recipient. The installer uses the existing `/connect/` HTTPS route.

MCP grants apply to exact tool names or explicitly to all current and future tools on the connection. This includes the bundled and legacy MCP routes. Native Git grants apply to a repository and operation. Existing broader connection shares remain valid. Integration Admin manages changes from Discord. Discord grants can also cover threads under an approved parent with separate permissions. The bot needs the corresponding permissions in Discord. Each integration operation goes through Luna. A standing grant can target all downstream agents when explicitly approved by the administrator.

Access requests, grants and browser authentication state live in the broker database. For a worker-only move, reconnect it to the same trusted integration service. Move broker state with its credentials through a private, access-controlled backup when migrating the broker itself. Pair new browsers after a hostname change.
